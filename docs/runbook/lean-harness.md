# 위험 기반 Lean Harness

## 상태와 권위

- 상태: Approved
- 승인 기준: `PCC_V5`
- 적용 시점: 현재 `main`에서 시작하는 새 작업

이 문서는 작업 등급, 저장소 준비와 실제 운영 실행 구분, 산출물·QA·검증 조건, delta-only Codex 명세, 복구와 비소급 원칙의 권위 원본이다. 다른 문서는 이 기준을 반복하지 않고 참조한다.

기존 작업 ID 디렉터리, 과거 보고서·인수인계와 역사 branch는 소급 수정하지 않는다. 등급 또는 실행 구분이 없는 기존 산출물은 validator의 명시적 legacy 옵션으로만 검사한다.

## 작업 등급과 실행 구분

| 등급 | 판정 기준 | 기본 검증 |
| --- | --- | --- |
| 경량 | 외부 계약·데이터·보안·운영 영향이 없는 한 역할의 작은 변경 | PR과 가장 작은 관련 검사 |
| 일반 | 하나의 사용자 목적을 완성하는 저장소 변경 | PR과 관련 테스트·CI |
| 고위험 | 보안, migration, 공통 CI, 복구 또는 운영 계약 영향 | 명시적 승인, 관련 전체 검증, 복구 경계 |

등급이 불명확하면 일반으로 시작한다. 외부 계약, 데이터, 보안, 운영 또는 복구 위험을 발견하면 고위험으로 승격한다. 문서 비용을 줄이기 위해 등급을 낮추지 않는다.

등급과 별개로 실행 구분을 기록한다.

- `저장소 변경`: 코드·설정·문서·Runbook을 준비하고 검증하지만 Production·Cloud·운영 DB·Secret·비용 리소스를 실행하지 않는다.
- `실제 운영 실행`: Production·Cloud·운영 DB·Secret·비용 또는 실제 복구·전환을 수행한다.

저장소 준비가 고위험이어도 실제 운영 실행 승인을 포함하지 않는다. 실제 운영 실행은 별도 명시적 승인과 실행 증거가 필요하다.
실제 운영 실행은 반드시 `고위험` 등급이어야 하며 `경량` 또는 `일반` 등급으로 실행할 수 없다.

## 공통 PR 계약

모든 작업은 PR 본문에 다음 최소 정보를 기록한다.

- 작업 ID
- 작업 등급
- 실행 구분
- 목적과 변경 범위
- 실행한 검증 또는 미실행 이유
- 남은 위험 또는 복구 경계

PR은 `.github/pull_request_template.md`의 6개 핵심 구획을 사용한다. 대안, 전환·migration, QA, 인수인계와 실제 운영 적용 전후 증거는 해당 작업에 필요할 때만 추가한다. 빈 placeholder는 정보로 보지 않는다.

## 보고서

보고서는 기본 생략한다. 보고서가 없다는 생략 사유도 요구하지 않는다.

다음 중 하나일 때만 `docs/reports/<TASK-ID>/`에 작성한다.

- 실제 Production·Cloud·운영 DB·Secret·비용 작업 실행 결과
- migration, restore, rollback 또는 데이터 변환 결과
- PR만으로 보존하기 어려운 장기 판정
- 후속 작업의 권위 입력이 되는 실행·복구 증거
- 사용자가 별도로 요구한 경우

일반·고위험 저장소 준비 작업도 PR·CI·테스트·Runbook으로 충분하면 보고서를 요구하지 않는다. 보고서가 존재하면 최소한 목적, 결과 또는 증거, 위험·제한을 포함한다.

`실행 구분: 실제 운영 실행`이면 보고서가 필수이며 다음 증거를 포함한다.

- 명시적 승인 근거
- 적용 전 확인
- 적용 후 확인
- 독립 확인
- 복구·rollback
- 미실행 항목과 남은 위험

미실행 항목과 남은 위험은 서로 다른 정보로 기록한다. 하나의 결합 구획을 사용하면 두 항목을 명시적으로 구분한다.

## 인수인계, QA, Runbook과 ADR

인수인계는 실제 다음 역할 또는 운영자가 결과를 입력으로 사용할 때만 작성한다. 인수인계가 없다는 구획이나 생략 사유를 요구하지 않는다.

QA 계획이나 결과는 다음 조건에서만 요구한다.

- 새 사용자 흐름 완성
- 인증·인가 변경
- 결제·재고·구독 상태 전이
- migration·데이터 손실 위험
- 여러 모듈의 통합 흐름
- 실제 결함의 독립 재현·재검증

QA가 필요하지 않으면 QA 구획·경로·생략 사유를 요구하지 않는다. 고위험 작업의 독립 확인은 별도 QA, 독립 CI 환경 또는 사용자가 승인한 동등한 경로로 충족할 수 있다.

반복 실행·중단·복구 절차가 있을 때만 Runbook을 작성한다. 지속적인 기술 선택과 trade-off가 있을 때만 ADR을 작성한다. 외부 계약이 불변인 내부 구현 선택은 별도 결정 문서를 기본 생성하지 않는다.

## Validator 경계

Validator는 구조적으로 판별 가능한 최소 안전 누락만 차단한다.

- PR의 공통 최소 정보와 빈 placeholder
- 충돌하거나 유효하지 않은 등급·실행 구분
- 존재하는 보고서의 목적·증거·위험
- 실제 운영 실행의 보고서와 필수 실행 증거
- 명시적 legacy 모드가 없는 과거 형식 사용

Validator는 승인 품질, 위험의 의미, QA 충분성, 인수인계 필요성 또는 운영 결과의 진위를 대신 판정하지 않는다.

## Delta 추출과 경량화

Codex 명세에는 현재 작업에서 달라지는 내용만 추출한다. 기본 구조는 다음으로 제한한다.

```text
작업 ID·등급·역할
기준 ref
목표
변경 범위
제외 범위
검증
중단 조건
Git·PR
```

프로젝트 전체 배경, PCC 원문, `AGENTS.md`·Skill 전체 규칙, template 원문과 공통 Git 절차를 복제하지 않는다. 작업 추적 metadata, 실행 환경 정보와 원격 상태도 Prompt 본문에 복제하지 않고 이를 관리하는 시스템 또는 PR 필드에 둔다. 공통 절차는 다음 한 줄로 참조한다.

```text
공통 안전·Git 절차는 현재 경로 AGENTS.md를 따른다.
```

실제 운영 실행 금지는 저장소 준비 명세에 한 번 명시한다. 권장 길이는 경량 300~700자, 일반 700~1,400자, 고위험 1,200~2,400자, 후속 수정 150~500자이며 경고 기준일 뿐 CI 차단 조건이 아니다.

### Final Lightweight Delta Prompt

작업 전달 직전에는 중간 토론과 이미 반영된 설명을 제거하고 위 기본 구조만 남긴 최종 경량 Delta Prompt를 사용한다. Validator는 필수 metadata의 존재와 구조적으로 판별 가능한 안전 계약만 검사하며, Prompt 길이·설계 품질·architecture 판단을 대신 차단하지 않는다.

## Harness feedback loop

반복 실패나 누락이 실제 검증·PR evidence로 확인될 때만 canonical Harness를 보완한다. 한 작업의 취향이나 일회성 예외를 공통 규칙으로 승격하지 않으며, `AGENTS.md`·역할 문서·Skill에는 실행 차이만 남기고 이 문서의 공통 계약을 복제하지 않는다.

## 복구와 비소급

- 저장소 변경은 일반 revert PR로 되돌릴 수 있어야 한다.
- 실제 운영 실행은 승인된 Runbook의 rollback·복구 경계와 증거를 따른다.
- reset, rebase, force push, history rewrite 또는 과거 산출물 수정으로 복구하지 않는다.
- 기존 정상 fixture와 legacy 산출물은 명시적 legacy 경로에서 계속 검증한다.
