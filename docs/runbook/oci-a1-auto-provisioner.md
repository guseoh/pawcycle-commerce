# OCI Tokyo A1 Auto Provisioner

Task ID: `OPS-OCI-A1-002`. Repository preparation only; installation, IAM changes and activation require a separate Operations Gate. Never use live LaunchInstance to test this implementation.

## Execution and existing monitoring

The [hourly read-only Capacity Watch and Discord Health workflow](oci-a1-capacity-watch.md) remain unchanged. This worker runs independently on a chosen Linux/systemd host. It imports the existing Capacity Report parser and fixed target constants; it does not use GitHub Issues for locking or launch state. The existing hourly AVAILABLE/daily health notifications remain separate from the worker's success, fatal-stop and stale-run notifications.

`pawcycle-a1.timer` requests a tick every 60 seconds (`AccuracySec=1s`). This is a best-effort host timer, not a hard real-time SLA. systemd does not start another instance of an active oneshot service. An OS file lock also excludes direct CLI/second-process overlap throughout API calls, persistence and notifications. A tick longer than 60 seconds delays subsequent checks. There is no loop that launches concurrent requests to catch up.

Only one designated machine is allowed: its `/etc/machine-id` SHA-256 must match the protected configuration, and the operator must attest that all other executors are fenced. Do not clone that machine ID. This is a single-executor deployment, not a distributed lock. The provisioning identity must not be used by another launcher. On host replacement, fence/revoke the old executor **first**, preserve state and STOP, and inspect OCI before approving a new machine binding. Without that fencing, activation is prohibited.

## State, failures and cost gates

The default configuration and initialized state are `DISABLED`. Each CLI call performs one tick. Protected configuration selects `dry-run` (all read-only preflight checks, even if unavailable) or `enabled`. Durable terminal modes are `provisioned` and `halted`; configuration cannot clear them. Missing/corrupt state fails closed. Initialization is explicit, refuses existing state/STOP, and makes no OCI call.

`state.json` stores an immutable-plan hash, a dedicated retry token, request phase, instance ID and notification flags. Updates use atomic replace, file fsync and directory fsync on Linux. Launch intent is durable **before** LaunchInstance. Never delete, regenerate, restore an older copy of, or edit this state to retry a request. Keep `/var/lib/pawcycle-a1` on durable local storage with mode 0700, preserved across reboot and host recovery; ephemeral container filesystems are unsuitable.

| Observation | Action |
| --- | --- |
| OUT_OF_HOST_CAPACITY report | No launch or alert; next 60-second tick |
| AVAILABLE | Fresh preflight, then launch once if enabled; availability alone is not success |
| Definitive capacity rejection from launch | Return to polling, retaining the token |
| HTTP 429 | Same-token retry after 60/120/240/480 seconds; fifth transient failure halts |
| Read-side 5xx/transport error | Bounded exponential backoff (maximum 900 seconds) |
| Launch 5xx/timeout/lost response | Persist pending intent; back off and reconcile tagged instances; **never automatically launch again** |
| Pending request absent from inventory | Recheck after 60 seconds; after 15 minutes halt for manual investigation, retaining token |
| Known instance PROVISIONING/STARTING | Track by ID and tags; after 30 minutes halt |
| Authentication, permission, quota, configuration or cost error | Sticky halt and Discord alert; no permission expansion or resource deletion |
| RUNNING with matching image/shape/AD/compartment/request tags | Persist provisioned and STOP, then notify; stop only the new provisioner timer |

OCI SDK retries are disabled. A token may expire or be invalidated by OCI; this worker never relies on an expired token to resolve uncertainty. A successful launch followed by a failed notification remains provisioned and cannot create a second VM. A manual terminal-state tick retries an undelivered terminal notification only. Discord may duplicate a notification if delivery succeeds but its acknowledgement/state write is lost; VM safety does not depend on notification exactly-once delivery.

Before launch, the adapter enumerates the root and **all** non-deleted compartments with `access_level=ANY`, fully paginates instances and regional boot/block storage, and fails on unreadable resources. Any existing non-terminated A1 (including stopped or terminating and regardless of display name) blocks this deliberately conservative single-instance worker. An existing target name/deployment tag also blocks. All root/compartment boot volumes across home-region ADs and block volumes count toward 200GB, including volumes not attached to VMs. Remaining CPU/memory/storage service-limit and compartment-quota availability must be known and sufficient; unknown or unsupported limit metrics halt instead of assuming capacity.

Tokyo must be the tenancy's home region. The fixed plan is 2 OCPU / 12GB / 50GB, with no public IPv4/IPv6 assignment, no custom/Marketplace image, no extra volumes or backup policy. Only approved Oracle platform Ubuntu/Oracle Linux images compatible with A1 and fitting 50GB are accepted. Approval includes the ARM64 architecture and free image licence. The existing subnet, VCN, security lists, NSGs and route-table snapshot must match the approved hash. The worker creates only the instance's required primary VNIC and boot volume through LaunchInstance, using that existing network.

The Limits API is **not** proof of free billing eligibility. The owner must verify current account-specific Always Free entitlement, current billing/monthly consumption and image/storage cost before activation, then attest in protected configuration. This attestation expires within 24 hours; renew only after checking again. No resource-policy/budget API provides a transactional no-charge guarantee. Fence competing/manual provisioning and resizing during the activation window; if that exclusivity cannot be maintained, do not enable. Existing usage, network drift or unknown inventory always blocks. Paid fallback is never attempted.

References: [current Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm), [Limits API availability and its missing-data caveat](https://docs.oracle.com/en-us/iaas/tools/python/latest/api/limits/models/oci.limits.models.ResourceAvailability.html), [retry-token semantics](https://docs.oracle.com/en-us/iaas/tools/python/latest/api/core/client/oci.core.ComputeClient.html#oci.core.ComputeClient.launch_instance).

## Identity and minimum permissions (proposal only)

Keep the existing report-only user/key unchanged. Create a separate dedicated provisioner identity only after approval. Do not grant `manage all-resources`, `manage instance-family`, deletion, networking creation, IAM mutation, or quotas mutation. The following are **policy design inputs**, not an applied policy or an instruction to run them blindly:

| Scope | Required permissions / resource types |
| --- | --- |
| Tenancy read inventory | inspect compartments; inspect region-subscriptions/availability-domains; read instances and volumes/boot-volumes across every relevant compartment; read resource-availability through `resource-availability` |
| Approved compartment | manage `compute-capacity-reports` for COMPUTE_CAPACITY_REPORT_CREATE; INSTANCE_CREATE through a permission-filtered instances policy; INSTANCE_READ/INSPECT for tracking |
| Approved image | INSTANCE_IMAGE_READ through read instance-images; use only a reviewed free platform image |
| Approved existing subnet | VNIC_CREATE/VNIC_ATTACH and SUBNET_ATTACH, with VNIC_READ/INSPECT for required use; restrict to approved compartment/subnet where IAM supports it |
| Approved existing NSGs, if any | NETWORK_SECURITY_GROUP_UPDATE_MEMBERS and VNIC_ASSOCIATE_NETWORK_SECURITY_GROUP; inspection/read for fingerprinting |
| Existing network reads | read virtual-network-family resources needed for GetSubnet/GetRouteTable/GetSecurityList/GetNetworkSecurityGroup/ListNetworkSecurityGroupSecurityRules; no create/update/delete of rules/routes |

Consult Oracle's [operation-to-permission table](https://docs.oracle.com/en-us/iaas/Content/Identity/policyreference/corepolicyreference_topic-Permissions_Required_for_Each_API_Operation.htm), [core policy reference](https://docs.oracle.com/en-us/iaas/Content/Identity/Reference/corepolicyreference.htm) and [Limits policies](https://docs.oracle.com/en-us/iaas/Content/General/service-limits/overview.htm). Draft statements should use `where request.permission = 'INSTANCE_CREATE'` (plus separately scoped read grants), rather than unrestricted manage. Review the LaunchInstance boot-volume side effects and account-specific permission dependencies against those official tables. Read-only dry-run cannot prove INSTANCE_CREATE is granted; authorize it through policy review, not a trial VM. Missing permissions halt; do not broaden grants to make a test pass. No policy is created or changed by this PR.

## Installation and Operations Gate

1. Choose a continuously available Linux host with Python 3.12, systemd, outbound HTTPS, accurate UTC time, unique machine ID and durable storage. This does not depend on the current E5 host. If E5 is chosen, reclamation/shutdown stops **both** worker and local health checks. An external host heartbeat is necessary to detect total host failure.
2. Approve the exact tenancy/compartment, Tokyo AD, free platform ARM64 image, existing subnet/VCN/NSGs/security lists, SSH public key and current network rules/routes. Review private-IP administration/access because public IP assignment is disabled. Do not attach the operating DB, deploy PawCycle, reset an OS or terminate E5.
3. Review IAM and free entitlement/billing, all-compartment inventory and 50GB remaining storage. Explicitly fence every other automated/manual launcher. Record an approval expiry no more than 24 hours ahead in epoch seconds. Real values stay on the host, not in this repository/PR.
4. After installation approval, create service user `pawcycle-a1`; create `/etc/pawcycle-a1` (root-owned), `/opt/pawcycle-a1/scripts` (root-owned), and `/var/lib/pawcycle-a1` (service-owned, 0700). Copy the two provisioner Python files and existing `oci_a1_capacity_monitor.py` into scripts. Create `/opt/pawcycle-a1/venv` and install the existing pin `oci==2.185.0`. Do not copy an OCI key from the monitor identity.
5. Copy `infra/oci-a1/provisioner.example.json` to `/etc/pawcycle-a1/provisioner.json`; fill approved values while keeping mode DISABLED. Protect it from service/user modification (root-owned, service-readable). Compute the host hash with `python3 -c 'import hashlib,pathlib; print(hashlib.sha256(pathlib.Path("/etc/machine-id").read_bytes().strip()).hexdigest())'`. Provide an OCI SDK config at `/etc/pawcycle-a1/oci-config` with region Tokyo and the dedicated key stored service-readable, 0600. Protect both key and config; do not print them.
6. Create a root-owned, service-readable `/etc/pawcycle-a1/worker.env` with `OCI_CONFIG_FILE=/etc/pawcycle-a1/oci-config` and the protected `DISCORD_WEBHOOK_URL` (Discord official HTTPS webhook). Do not echo it into logs or shell history. systemd loads this environment without putting credentials into unit files.
7. Before state initialization, temporarily select `dry-run` and use the CLI `--network-fingerprint` with `--config ... --state-dir ...` to obtain only the network snapshot hash. Independently review the referenced rules/routes and approve that hash. This read-only action is not a launch dry-run and requires no state. Restore DISABLED, set the reviewed hash and all approvals, then run `.../venv/bin/python .../scripts/oci_a1_provisioner.py --config /etc/pawcycle-a1/provisioner.json --state-dir /var/lib/pawcycle-a1 --initialize` as the service user. It must report DISABLED with no OCI calls.
8. Change only mode to `dry-run` and run a single tick as the service user with the environment loaded securely. Confirm full preflight succeeds, network hash matches and state remains dry-run; no launch permission is needed for this check. Inspect safe journal status and local state without publishing resource identifiers/token. Run the Fake OCI suite and the Linux/systemd fixture in an isolated CI environment. State's immutable plan hash must match; changes to image/network/executor require a separately reviewed recovery procedure, not editing the hash.
9. **Separate activation approval:** verify current account, approval expiry, exclusive executor and unchanged dry-run plan. Copy only the four new unit files to `/etc/systemd/system`; run `systemd-analyze verify` on them and `systemctl daemon-reload`. Set mode `enabled`, then `systemctl enable --now pawcycle-a1.timer pawcycle-a1-health.timer`. This is the point that permits unattended LaunchInstance; there is no later human confirmation on AVAILABLE. Existing PawCycle application/deploy/certificate/observer timers must not be touched.
10. Verify the 60-second ticks through `journalctl -u pawcycle-a1.service` and `systemctl list-timers`; after genuine success confirm the OCI instance is RUNNING with the exact approved plan/tags, state is provisioned, STOP exists, the provisioner timer is inactive, and Discord success arrived. The health timer remains but sends no terminal-state stale alerts. Host reboot may reactivate an enabled timer once; durable terminal state prevents API calls and stops it again.

## Emergency stop, health and recovery

- Approval expires: a single Discord `approval_expiring` alert is attempted during the final hour, with delivery retries on later ticks if necessary. At expiry the worker enters `approval_expired` and blocks new launches while retaining the token, phase, request timestamp and instance ID; the timer continues running. To renew, the owner must recheck billing, free entitlement, image, network and executor fencing, then update only `approval_expires_at` in the protected config to a later epoch no more than 24 hours ahead. As the service user run `/opt/pawcycle-a1/venv/bin/python /opt/pawcycle-a1/scripts/oci_a1_provisioner.py --config /etc/pawcycle-a1/provisioner.json --state-dir /var/lib/pawcycle-a1 --reapprove`. Editing the timestamp alone cannot resume the worker. The immutable plan must still match. The next enabled tick reconciles any pending/tracking request first; unresolved requests never cause a second launch. For ready state, the next launch still requires the complete fresh preflight. Never reset or delete state as part of renewal.
- A state created by an earlier version has no durable approval binding and enters `approval_expired`; apply the same explicit reapproval procedure without resetting its existing token or phase.
- Read-only preflight: after a separately approved installation and with valid approval and a `ready` phase, set protected mode to `dry-run` and run the normal worker CLI once as the service user. It queries capacity and executes the same inventory, Limits, image and network checks even when capacity is unavailable; it does not call LaunchInstance. Confirm `dry-run` result and network hash without copying OCI identifiers or secrets to logs. Restore the approved operating mode afterwards. A pending or tracking request instead returns `pending_requires_reconciliation` without altering it; restore enabled mode after reapproval to reconcile it first. This procedure has not been run against OCI: **NOT_RUN**.
- Limits contracts: `compute/standard-a1-core-count`, `compute/standard-a1-memory-count`, and `block-storage/total-storage-gb` are AD-scoped. The worker sends the target AD and compartment for availability, then sums compute usage from the tenancy in every AD. Unsupported metrics, HTTP 404/403, missing values or insufficient availability halt. See [Compute quotas](https://docs.oracle.com/en-us/iaas/Content/Quotas/Concepts/resourcequotas_topic-Compute_Quotas.htm), [Block Volume quotas](https://docs.oracle.com/en-us/iaas/Content/Quotas/Concepts/resourcequotas_topic-Block_Volume_Quotas.htm) and [Limits API](https://docs.oracle.com/en-us/iaas/tools/python/latest/api/limits/client/oci.limits.LimitsClient.html).

- Emergency stop: `systemctl disable --now pawcycle-a1.timer`; change protected mode to DISABLED and stop `pawcycle-a1.service`. A request already sent may still finish in OCI. Retain state and inspect it plus OCI before any restart. For compromised/lost hosts, revoke the dedicated key as a separately approved IAM action.
- Every five minutes the independent local health service checks `last_ok`. More than three minutes without a successful tick sends one stale alert per incident. Recovery silently rearms that alert. It makes no OCI calls. Local lock contention waits for the next health tick. On persistent lock/hung process or total host failure the local health checker cannot establish liveness; monitor service journal/timer and host externally. Do not interpret a lack of Discord alerts as proof of health.
- Fatal stops and success create a STOP latch; `ExecStopPost` stops only `pawcycle-a1.timer`, including on a local execution failure. A failed Discord delivery does not remove STOP or undo a VM. Invoke a terminal tick manually after fixing notification access to retry that notification.
- For an uncertain launch, do not clear STOP, reset state, rotate the token or relaunch. Query all compartments by request/deployment tags, inspect known instance ID and OCI Audit/LaunchInstance history, and establish whether the original request succeeded. The worker never deletes or repairs OCI resources. No automated "reset" command exists. Lost state requires manual incident resolution, old-host fencing and a separately approved new plan; it is not safe to initialize over uncertainty.
- Changes to approved launch settings invalidate the stored plan. For a known never-launched state, retire/archive it under operator review, fence the old identity/host as appropriate, then approve a new deployment and initialization. For pending/tracking/provisioned state, resolve the existing VM/request first. Renewing approval expiry and switching dry-run/enabled do not change the launch plan.
- Repository rollback is a revert PR. Operational rollback is disabling only these new timers, preserving state and revoking the dedicated identity when approved. It never includes deleting the new VM, existing boot volumes or existing E5.
